1About this guide

This guide explains how the East Forsyth Blue Regiment Band website is laid out and how to keep its content up to date through the Content Management System (CMS). It is written for the content administrator, the person who manages pages, photos, the calendar, sponsors and forms day to day. You do not need any coding tools. Everything in this guide is done in a web browser at efhsband.org/admin.

WhoLooks after
Content administrator (you)Words, photos, calendar events, sponsors, staff listings, forms, social links and editor accounts, all through the CMS.
Trevor Olsen, site hostThe domain, Cloudflare hosting, the database, GitHub code, deploys, email and payment connections, and anything that needs a code change.
Good to knowThis guide matches the website as of October 2026 (the release that adds the visual page editor). The CMS shows each person only the tools their account allows. If a button in this guide is missing for you, see Section 4 (accounts and permissions).

Conventions: menu items and buttons appear in bold, exactly as they are labeled on screen. “Menu → Item” means click the item in the CMS left-hand menu. On a phone, tap Menu at the top of the CMS to open the same list.

4Logging in, accounts and permissions

Logging in

  1. Go to efhsband.org/admin, or click Login in the top link bar.
  2. Enter your Username (your email address) and Password. The eye button shows or hides what you typed. Click Log in.
  3. You land on the Dashboard. Its cards and the left menu show only the tools your account can use. View Site opens the public homepage.
  4. When you are done, click Log Out (bottom of the left menu, or top bar on a phone).
  • A sign-in lasts 24 hours. After that, log in again.
  • Change Password (bottom of the left menu) asks for your current password and a new one twice. The minimum is 8 characters.
  • There is no self-service “forgot password” link. A Super Admin sets a new temporary password for you (see below).

Roles

RoleWhat it means
Super AdminHas every tool and permission. Only Super Admins can open the Security Log, download this guide, create or promote other Super Admins, change the Boosters dues setting, and preview the site while maintenance mode is on.
EditorSees only the tools given by the permission checkboxes on that account.
Site policyOnly Super Admins manage user accounts and site settings. When you create editor accounts, leave Manage users and Site settings, home text, logo unchecked. That keeps account changes, the logo, the top links, social connections and maintenance mode with the Super Admin.

Creating or changing an account (Super Admin)

  1. Menu → Users (the screen is titled User Management). Existing accounts are listed under Team Members with role, Active/Disabled status, permissions and last login.
  2. Click New user. Under Invite New User, fill in Email / Username and Display name. Set a temporary password of at least 8 characters. Choose a Role (Editor or Super Admin - all permissions) and keep Active checked.
  3. Tick the Global permissions and Page edit permissions the person needs (tables below), then click Send Invite / Save User.
  4. Give the person the temporary password yourself and ask them to use Change Password after their first login. Saving the account does not send them an email.
  5. To reset a password, click Edit on the account, type a new password and save. When editing, the password field can be left blank to keep the old one. To stop someone logging in, uncheck Active. Delete removes the account, and you cannot delete your own.

6Editing content

6.1 Pages editor

  1. Open Home from the Pages list, or click Settings beside any page if you can manage all pages.
  2. The Live page preview looks like the public page. Click any text to edit it. This older editor is still used for Home and for title / address / menu / Active settings.
  3. Select text, then use the Formatting bar: B, I, U, Color, Size (Normal, Small, Medium, Large, Extra large), • List and Photo (insert an image at the cursor, then drag a corner to resize or use Delete photo).
  4. An Unsaved tag shows you have changes. Click Save Changes to publish. If you try to leave with unsaved edits, the CMS offers Stay, Discard or Save & leave.

With Add/remove/manage all pages you also get Page settings: Page title, Slug, Path, Navigation order, Page layout, Active / visible on the public site, Add callout, and the Add Page button. Editors with a single page checkbox see only their pages in the list and do not see Settings.

  • To switch a page off (show Coming Soon and remove it from the menu), open Settings, uncheck Active, and save. Check it again to bring the page back. This is how Ensembles will go live.
  • Home page: the hero headline and top links live in Site Settings. The fundraiser, calendar, sponsor, officer and photo sections fill in automatically (Section 2). Home is not in the visual editor yet.
  • Most other pages open in the visual editor (next section). Live lists, calendars, forms, and donate buttons stay locked in place so they keep working on the public site.

6.2 Visual page editor

Click a page name under Pages to open the drag-and-drop editor at /admin/visual/ and that page’s address. You need that page’s checkbox or Add/remove/manage all pages. Home is not in this editor yet. Use a computer or tablet — phones show a notice and send you back to the live page or the CMS.

A banner reads “This page is being edited” and reminds you that visitors still see the published page until you publish. The banner buttons are:

ButtonWhat it does
Add sectionAdds a ready-made block: Hero, Hero card, Text, Photo, Button or Dropdown (question and answer).
Undo / RedoSteps back or forward through your edits.
WidthPreviews the page at 1920, 1280, 768, 390 or 320 pixels wide, to check phones and tablets.
HistoryLists recent saves (Draft or Published, with time and name). It keeps the last 20 saves. Click one to restore it into the draft.
Save draftSaves your work without changing the live page.
PublishAfter a confirmation, replaces the live page content with what is on screen.
ExitReturns to the CMS. You are warned if you have unsaved changes.
  • Click any part of the page to select it. The small toolbar lets you Select parent, Move, Copy, change the Image, add a Link or Delete. Double-click text to edit it.
  • Yellow Live data — locked blocks (calendar, upcoming events, gallery, sponsors, staff, boosters, forms, contact, donate) cannot be edited. They keep showing live data on the public page.
  • Use Width 390 and 320 to scroll the whole page as a phone would see it. Before Save draft or Publish, the editor checks those widths. If something is too wide, it names the element and offers Publish anyway / Go back.
  • Change image lets you pick a photo already on the site or Upload a site photo. Uploads are added to the site photo library and appear in the public Gallery.
  • Links must start with / (a page on this site), https://, mailto:, tel: or #.
  • Restoring an old version puts it in the draft only. Click Publish to make it live.
  • Every save counts toward the 20 kept versions, drafts included. Older versions drop off automatically.
ImportantPublishing replaces the page. Save a draft first, check every Width, then publish. If something goes wrong, open History, restore the last Published version and publish it again.

6.3 Calendar: the Schedule Board

The public Calendar, the Home calendar list, the Boosters meetings card and the red IMPORTANT banner all come from Menu → Schedule Board.

  1. Pick the month and year at the top. The colored track buttons filter what you see.
  2. Click + New event, the + on a day, or double-click a day. Click once to select an event and double-click it to edit.
  3. Fill in Title, Date, optional End date, All day or Start/End times, What, Location and Description. The description can use B, I, U, Link (Text to click / Goes to), Color and Size.
  4. Repeat → Yes creates one event for each chosen weekday in the chosen months. Use Skip date → Add exception for days off.
  5. Click Save. To move an event, drag it to a new day (on phones, press and hold, then drag). Delete asks first, and deleting a meeting also removes it from the Boosters page.
What (track)Effect on the site
Games · Rehearsals · Trips · OtherShown on the Calendar. Routine rehearsals are left out of the short Home list.
MeetingsAlso listed on the Boosters page meetings card.
IMPORTANTTagged IMPORTANT, and shows the red banner under the header on every public page from 7 days before the date (or end date) through that day. The text reads “IMPORTANT: title date!”. If the description has a link, the banner’s Click Here goes there. Otherwise View details opens the Calendar.

Finished (Super Admin, President or Vice President) emails calendar email subscribers that the schedule was updated. Use it once after a batch of changes, not after every edit. Saving Schedule Board events does not email anyone by itself.

TipUse IMPORTANT sparingly, for deadlines such as picture day, forms or payments. Every visitor sees the banner on every page for a week.

6.4 Fundraising cards

You do not build fundraiser cards by hand. They are made from the Schedule Board and the Fundraising page:

  • Any upcoming Schedule Board event whose title or description mentions fundraiser/fundraising, mattress or auction counts as a fundraiser.
  • On Home, the next fundraiser becomes the “Next fundraiser” card and the large featured card. Later fundraisers appear as smaller cards. The featured flyer is the first photo in the Fundraising page text.
  • On the Fundraising page, each upcoming fundraiser becomes a card with When/Where details and Support and Details buttons. Cards pair up in order with the photos placed in the Fundraising page text.
  • If the text says must attend, the card shows a red “Band members must attend” tag.
  • To change a card, edit the event on the Schedule Board, or the flyer photo in Pages → Fundraising. When the event date passes, its date details drop off. Remove its flyer from the Fundraising page text if you no longer want that card.

6.6 Photos and gallery

  1. Menu → Photos (titled Photo gallery). Click New photo.
  2. Choose one or more JPG, PNG, WEBP or GIF files. Large photos are resized automatically to under 1.9 MB before upload.
  3. Enter Alt text (a short description for screen readers, which is required) and an optional Title / caption, then click Upload photo.
  4. Drag rows to change the gallery order. Edit changes alt text and caption.
ImportantDelete removes the photo right away, for good. There is no trash or undo. The CMS refuses to delete a photo still used as a staff or booster photo, sponsor logo or the site logo, but it does not check photos placed inside page text (Fundraising, Join). Deleting one of those leaves a broken image.

If Instagram auto-post is switched on (Social Media), each new gallery upload is also posted to Instagram.

6.7 Directors & Staff (and Booster Members)

Menu → Directors & Staff → Add Staff Member. Enter Name, Role / title, Short description and a photo (Upload photo or Photo URL). Keep Show on Directors & Staff page checked, then click Save Staff Member. A Live Preview shows the result. Drag rows to reorder, or use Edit / Delete. Edit page text changes the page heading and intro.

Band Boosters → Booster Members works the same way for booster officers (Add Booster Member, Show on Boosters page, Edit Boosters page). These people also appear on Home.

6.8 Forms and submissions

Menu → Forms opens the Form Builder. Super Admins, the President, users with the Forms permission, and anyone a Super Admin adds under Who can use Form Builder can use it.

  1. Under Create a form, type a Form title and click Create form. The title becomes the public page address (for example Band Trip Form → /band-trip-form.html).
  2. Click items under Add Form Element (Heading, Short Text, Long Text, Email, Phone, Number, Date Picker, Dropdown, Single Choice, Multiple Choice, Paragraph, Price List). A form can have up to 40 fields. Drag fields to reorder them, and select one to edit it under Properties.
  3. Under Email this form to, pick who receives the completed PDF. Click Save form, then Open page to check it.
  • Your forms lists each form with Edit and Delete. Delete also removes its public page, and cannot be undone. The built-in Letterman Jacket Order Form is listed here too.
  • Email in-kind PDFs to sets who receives In-Kind Donation forms. Click Save access settings.
  • Recent submissions lists the latest entries with Download PDF, and shows Emailed or Not emailed for each.

6.9 Contact form

Menu → Contact Form. Click Add Topic, enter a Topic label, keep Active on contact form checked, choose one or more CMS users under Deliver messages to, then click Save Topic. Only active topics with at least one recipient appear on the public form. Recent Messages keeps every inquiry, even if email delivery fails.

6.10 Email subscribers

  • Visitors sign up on the Calendar page (“Email calendar updates”) and the Fundraising page (“Email fundraising updates”). The short address efhsband.org/subscribe opens the Calendar signup.
  • Emails go out only when you choose: Finished on the Schedule Board (calendar subscribers) or saving the Fundraising page with Notify email list checked (fundraising subscribers).
  • People unsubscribe with the link in the email or by replying STOP.
  • The CMS has no screen that lists subscribers. Ask the site host if you need a count or an export.

6.11 Push notifications (Notify Me)

Visitors can tap the bell (Notify Me) in the main menu to allow browser notifications about calendar updates on supported browsers. In Brave, the visitor must turn on Google push messaging. The CMS has no screen for writing or sending a push message, and Schedule Board changes do not send push notifications in this release. Use Finished (email) to tell families about schedule changes. Contact the site host if you need push alerts.

6.12 Social and top links

  • Social icons: Menu → Social Media → Account links. Enter the Facebook, X, Instagram, YouTube and TikTok page addresses and click Save social links. A blank address shows a faded placeholder icon.
  • The same screen connects the band’s Facebook Page and Instagram (Connect Facebook, Connect Instagram, Refresh status, Disconnect), lets you compose a Facebook post (now or scheduled), and turns on Auto-post new gallery photos.
  • Top links: Menu → Site Settings → Top utility links. Each link has a label, an address and Same tab/New tab. Use the arrows to reorder, × to remove and Add for a new link (six at most). Click Save links.
Site policySocial Media and Site Settings require the Site settings permission, which is kept with Super Admins.

6.13 Site settings and maintenance mode (Super Admin)

Menu → Site Settings (titled “Home, title, logo, footer, and top links”) holds Site title, Hero title, Hero subtitle, Footer note and Logo URL, the Maintenance mode and Show band dues on Boosters switches, Save site settings, and Upload new logo. Do not replace the logo (Section 7).

  1. To take the site offline briefly, check Maintenance mode and click Save site settings.
  2. Visitors, and every account that is not a Super Admin, now see the maintenance page (“We’ll be right back.”). Super Admins can still browse the site, with a banner reading “Maintenance mode is on. Super Admin preview…” and a Back to CMS link.
  3. To go live again, uncheck Maintenance mode and save. The CMS confirms: “The public site is live again.”

6.15 Security log (Super Admin)

Menu → Security Log. Only Super Admins can open it. The log is append-only: no one can edit or delete a row, including Super Admins. D1 triggers abort any UPDATE or DELETE.

  • The screen opens on the current month in Eastern Time, with a month and year selector. Change those to look at an earlier month.
  • It shows 25 entries per page, newest first. Use « ‹ Page › » to move through the month.
  • Search by user, action (dropdown of known actions such as login, change.pages, mail.send), an optional date range, and free text. Free-text search looks at the decrypted summary, path, and details of the rows already loaded on that page. It does not search encrypted ciphertext in the database.
  • Download month PDF exports the selected month (and any user/action/date filters). Keep that PDF with your records.
  • Visual editor Save draft, Publish, and Restore appear as change.pages, with the page name and kind (draft, publish, or restore) in the summary. Opening a visual editor page adds page.edit.open.
  • Each sealed row still shows its own integrity flag. The screen also reports Chain intact or Break at entry #id for the hash chain on new rows.
  • If an audit write fails, the Worker logs it and the Security Log shows a warning such as N audit writes failed since <time>.
  • Verify integrity checks the SHA-256 hash chain for the selected date range without needing to edit anything. Download CSV and Download JSON include a signed chain-head hash for handing records to the school or police.
  • Start a new log generation is Super Admin only and needs Trevor’s authorization. It does not change or delete old rows. It writes a log.genesis row (reason, date, who started it, previous chain head, previous row count, and that the site has been logged since the original build) and continues the hash chain under a new key id (k2, k3, …).

A.2 Deploy process

  1. Start from a fresh clone of the release branch, then run npm ci (Wrangler is pinned in package.json).
  2. Run the tests: npm run test:worker and npm run test:cms-guide-pdf.
  3. Test copy first: npm run check:worker-assets && npm run sync:worker-assets && npm run check:worker-public && npx wrangler deploy -c wrangler.dev.toml. Then check efhsband-dev: home, calendar, /admin login and the changed screens.
  4. If the release includes a schema file (this one has migrations/2026-10-03.1.sql), apply it at deploy time with npx wrangler d1 execute efhsband-db --remote --file …. It is idempotent, and the Worker also applies it automatically when it sees an older schema.
  5. Production: npm run deploy:worker. This checks wrangler.toml, syncs the assets, confirms every published file is git-tracked, then runs wrangler deploy to efhsband-live.
  6. Verify the live site, logged out and logged in, with a hard refresh. To roll back, use Cloudflare → Workers → efhsband-live → Deployments, or redeploy the previous commit.
ImportantNever use npm run deploy:pages for the public domain, never rename the Worker away from efhsband-live, and never point [assets] directory at ./assets.

A.4 Backups

  • Built in: D1 Time Travel allows point-in-time restore of efhsband-db to any minute in the last 7 days on the Free plan (npx wrangler d1 time-travel restore efhsband-db --timestamp=…).
  • Code: GitHub holds the full history. Any commit can be redeployed.
  • No scheduled export job exists in the repository. Recommended: a monthly npx wrangler d1 export efhsband-db --remote --output efhsband-db-YYYY-MM-DD.sql kept off-site in encrypted storage. The export includes photos, personal data and password hashes, so treat it as confidential.

A.6 Security log encryption key and “new log” procedure

The Security Log encrypts each new row’s details (IP, user agent, content excerpts, diffs, file hashes) with AES-256-GCM. The key is a Cloudflare Worker secret named AUDIT_LOG_KEY for generation k1, then AUDIT_LOG_KEY_K2, AUDIT_LOG_KEY_K3, and so on. Trevor does not hold or see the key. It must never exist outside Cloudflare’s secret store: not in git, wrangler.toml, chat, screenshots, or a file.

First install (deploy step only): generate and store the secret in one pipe so it is never assigned to a variable or printed. DEV uses a different random value than production. Do not set the production secret until the production deploy step.

openssl rand -base64 32 | wrangler secret put AUDIT_LOG_KEY --name efhsband-dev
wrangler secret list --name efhsband-dev
# Production, only at the prod deploy step:
openssl rand -base64 32 | wrangler secret put AUDIT_LOG_KEY --name efhsband-live
wrangler secret list --name efhsband-live

After the pipe, report only that wrangler secret list shows AUDIT_LOG_KEY. Do not read the secret back.

If the key is lost, or a new log must start (Trevor’s authorization required):

  1. Do not overwrite AUDIT_LOG_KEY. Old rows stay encrypted with the original secret and must remain readable.
  2. An authorized deploy agent pipes a fresh CSPRNG value into the next named secret, for example AUDIT_LOG_KEY_K2, using the same one-line openssl | wrangler pattern. Never print it.
  3. A Super Admin opens Security Log → Start a new log generation, enters the reason, types that Trevor authorized it, and confirms START NEW LOG.
  4. The Worker writes log.genesis (reason, UTC date, actor, previous chain-head hash, previous row count, note that the site has been logged since the original build) and continues the hash chain. Every new row stores its key id so generations stay distinct. Existing rows are not updated or re-encrypted.

Limits: the Cloudflare account owner can still decrypt because they control the Worker secrets and D1. Encryption protects privacy from anyone browsing raw D1. The hash chain plus a scheduled daily export of the chain head to an outside location is the stronger tamper-evidence plan; that daily export is not built yet.
